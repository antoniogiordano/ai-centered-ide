# PTY spike results

Date: 2026-07-31  
OS tested: macOS 14 (arm64), zsh. Windows/Linux: not executed on this machine — strategy: CI matrix job `spikes/pty` on `windows-latest` + `ubuntu-latest` before Phase 5 lands.

## Library

`node-pty@1.x`

## Checks

| Scenario | Result (macOS) |
| --- | --- |
| Interactive shell with explicit cwd/env | OK |
| Continuous output ~60s with timestamps | Scripted via `pnpm test:stream` |
| Resize mid-session | OK (`term.resize`) |
| Process-tree kill (`kill(-pid)` / `pkill -P`) | OK for sleep children; document Windows `taskkill /T` |
| High-volume output / event loop | Stress script; Python burst preferred over shell echo loops |

## OS differences (expected)

- **Signals:** POSIX process groups vs Windows job objects (`taskkill /T /F`).
- **Stderr:** node-pty merges PTY streams; product will tag chunks and optionally use separate pipes for non-PTY one-shot commands.
- **Quoting/paths:** shell-specific; product command policy must parse conservatively (Phase 5).

## Product takeaway

Wrap node-pty in Phase 5 PTY manager with mandatory timeout + tree kill; never expose raw PTY to renderer.

## Note
On pnpm install, `spawn-helper` may lose +x; run `chmod +x node_modules/node-pty/prebuilds/darwin-arm64/spawn-helper` (or postinstall).
